# Output Schema for Tabular File Understanding

This file defines the canonical artifacts produced by the skill. Agents may add fields, but should not remove the core fields because downstream agents rely on them.

## Artifact Layout

```text
<output_dir>/
├── table_manifest.json
├── table_profile.json
├── table_digest.md
├── ambiguities.md
├── data_locator_spec.json
└── data_locator_guide.md
```

## `table_manifest.json`

Required top-level fields:

```json
{
  "schema_version": "1.0",
  "source_file": "string",
  "file_name": "string",
  "file_type": "csv|tsv|xlsx|pdf|unknown",
  "file_size_bytes": 0,
  "created_at_utc": "ISO-8601 string",
  "profiler": {
    "name": "profile_tabular_file.py",
    "version": "1.0.0",
    "python_version": "string"
  },
  "mode": "sampled|full|limited",
  "capability_level": "basic|standard|limited",
  "output_control": {
    "policy": "full|balanced|compact|very-compact",
    "requested_policy": "auto|full|balanced|compact|very-compact",
    "reason": "string",
    "thresholds": {},
    "controls": {}
  },
  "features_available": [],
  "features_unavailable": [],
  "warnings": [],
  "tables": [],
  "domain_profile": {
    "dataset_type": "generic_table|macro_timeseries|sdmx_macro_timeseries|imf_bop_like",
    "confidence": "high|medium|low",
    "column_roles": {},
    "locator_outputs": ["data_locator_spec.json", "data_locator_guide.md"]

}
```

Each table entry should include:

```json

  "table_id": "string",

  "confidence": "high|medium|low",
  "warnings": [],
  "columns_omitted_by_output_policy": 0,
  "omitted_column_names_preview": []
}
```

## `table_digest.md`

Recommended sections:

```markdown
# Table Digest

## Source
## Profiling Capability
## Detected Tables
## Primary Table Guess
## Structural Interpretation
## Key Columns
## Sample-Based Statistics
## Warnings
## Recommended Next Questions
```

The digest should stay compact. Do not include hundreds of fields or rows. For very wide tables, group columns by pattern.

## `ambiguities.md`

Recommended sections:

```markdown
# Ambiguities Requiring Confirmation

## High Priority
## Medium Priority
## Low Priority
```

If no ambiguity is detected, still write the file and say:

```markdown
No major structural ambiguities were detected in the sampled profile. This does not guarantee semantic correctness.
```


## Adaptive Output Control

For large or very wide files, `table_profile.json` may be reduced by the adaptive output policy. This can affect:

- number of examples per column;
- number of top values per column;
- whether row samples are kept;
- number of detailed column profiles retained for extremely wide tables.

The original input file is never modified. The selected policy is recorded in `table_manifest.json` under `output_control` and summarized in `table_digest.md`.

See `references/adaptive-output-policy.md`.


## `data_locator_spec.json`

This artifact is generated by the reference profiler to help agents locate data inside macro/SDMX-like tables without loading the full dataset into context. It is still useful for generic tables, but confidence may be low.

Required top-level fields:

```json
{
  "schema_version": "1.0",
  "source_file": "string",
  "primary_table_id": "string or null",
  "dataset_type": "generic_table|macro_timeseries|sdmx_macro_timeseries|imf_bop_like",
  "confidence": "high|medium|low",
  "domain_preset": "auto|generic|macro-timeseries|sdmx|imf-bop",
  "column_roles": {
    "entity_column": "string or null",
    "indicator_column": "string or null",
    "counterpart_column": "string or null",
    "frequency_column": "string or null",
    "time_column": "string or null",
    "value_column": "string or null",
    "unit_column": "string or null",
    "status_column": "string or null"
  },
  "indicator_index": {
    "column": "string or null",
    "available": true,
    "unique_count_sample": 0,
    "top_values": [
      {"code": "string", "label": "string or null", "description": "string or null", "sample_count": 0}
    ],
    "mapping_required": true,
    "mapping_applied": false
  },
  "entity_index": {
    "column": "string or null",
    "available": true,
    "unique_count_sample": 0,
    "top_values": []
  },
  "time_coverage": {
    "time_column": "string or null",
    "frequency_column": "string or null",
    "overall_min_sample": "string or null",
    "overall_max_sample": "string or null",
    "frequencies_detected_sample": [],
    "by_frequency_sample": [],
    "mixed_frequency_sample": false
  },
  "observation_locator": {
    "recommended_key": [],
    "value_column": "string or null",
    "attribute_columns": [],
    "key_uniqueness_check": {
      "tested_on_rows": 0,
      "key_columns": [],
      "duplicate_key_count_sample": 0,
      "is_unique_in_sample": true
    },
    "locator_template": {}
  },
  "required_preprocessing": [],
  "warnings": []
}
```

Important interpretation rules:

- `*_sample` fields are sample-based and must not be treated as exhaustive unless a custom full scan is added.
- `column_roles` are inferred from column names and lightweight heuristics. Official SDMX DSD/codelists override these guesses.
- `mapping_required: true` means the profiler saw codes but did not receive a codelist CSV for human-readable labels.
- `recommended_key` is a practical automation key, not a guaranteed database primary key. Check `key_uniqueness_check`.

## `data_locator_guide.md`

A compact Markdown guide for humans and LLM agents. It should summarize:

- domain guess and confidence;
- inferred column roles;
- recommended observation key;
- value and attribute columns;
- indicator and entity/object code samples;
- time coverage and frequency caveats;
- preprocessing requirements before automated extraction.

## Complex Structures Not Fully Covered

The schema is intentionally conservative. The following structures may require custom extractors or optional libraries:

- multi-row headers and spreadsheet report layouts where dimensions are encoded in merged cells;
- cross-tab or matrix tables where time periods, countries, or indicators are spread across columns;
- multiple tables stacked in one sheet with repeated headers or footnotes between blocks;
- nested JSON/XML/SDMX-ML structures rather than flat CSV-like exports;
- hierarchical codelists or dimensions whose meaning requires an external DSD;
- PDF tables spanning pages, scanned PDFs, or layouts where text order does not match table order;
- Excel workbooks whose true values depend on formulas, hidden sheets, named ranges, PowerQuery, pivots, macros, or external links;
- geospatial/raster/array formats such as NetCDF, HDF5, GeoTIFF, shapefiles, or Parquet partitioned datasets;
- zipped dataset packages containing multiple related files and separate metadata dictionaries.
